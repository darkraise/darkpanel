# UI proof: M2 web hosts

**Contract:** docs/dforge/specs/2026-10-19-m2-fleet-lifecycle-design.md
**Fingerprint:** 818b682aa4967397
**Judge:** ship 818b682aa4967397 — docs/dforge/ui-ux/proofs/2026-11-11-m2-web-hosts.judge.md
**Platform:** web
**Viewports:** 375x812, 768x1024, 1440x900
**Themes:** light, dark
**Evidence:** local

Screenshots live under `.dforge/ui-ux/m2-web-hosts/`, named
`<id>-<viewport>-<theme>[-<state>].png`. Every name below exists for all six
viewport and theme pairs, and a row cites a narrow and a wide one. Two committed
Playwright specs, run in a real Chromium against the worst-case `mockApi`,
regenerate all of them. The worst case is 50 hosts, a 63-character host name, a
40-character version, 3 update transactions and 20 rollouts of 50 hosts.

- `web/e2e/m2-web-hosts.pw.ts` is the keyboard pass: 48 tests, every flow at every viewport and theme.
- `web/e2e/m2-web-hosts-states.pw.ts` forces each state by routing a read to hang, to answer 500 or to answer an empty list. It also screenshots the open form dialogs and the focus ring, and asserts no axe violation and no console error on every page and form dialog.

The pointer pass is the Vitest flow tests each row names.
