## Per-criterion notes

**Every Item Has Evidence (18).** Every contract item has a Results row, and the screenshots I opened show the item each row names:
- UX-3: the revoke dialog targets new-1, while the after-apply list shows the long-name host as Revoked. The keyboard test (`m2-web-hosts.pw.ts` lines 76-97) revokes `LONG_HOST_ID`, so the two screenshots come from different tests and both are correct.
- UX-9: the disabled screenshot shows "Start rollout" disabled, with host ids in place of names while the host list is unread. That is the UX-8 "id itself" fallback.
- The UX-5 address form and the UX-6 policy form before submit have no screenshot. They are covered by named tests (host-removal.test.tsx UX-5 and update-policy-dialog.test.tsx UX-6, UX-11).

**Built Matches Promised (18).**
- UI-1: the columns, the Pending (outline), Revoked (destructive) and Unsupported (destructive) badges, "Never seen", the "—" placeholders and "protocol N" all match the hosts board, in light and dark.
- UI-2: the Overview tab comes first, followed by three h2 cards. A pending host shows "—" for every fact, as the board does. The controller's own host replaces its removal controls with an explanatory line, which agrees with the visibility rules in UX-3 to UX-5.
- UI-3: card title "1.3.0 (stable)", the state badge, "Created … · updated …", the error alert, and the ordered host table all match the rollouts board.
- UI-4: `stateVariant` maps exactly the amended set, and `badges.test.ts` pins every case. `UI-4-1440x900-light-transactions.png` and `UI-4-375x812-dark-transactions.png` show the five in-progress states as grey `secondary` pills, rolled-back and failed as red `destructive`, and committed as blue `default`, each with the state as text. The global `pending` to `secondary` mapping does not reach the hosts page: `hosts.tsx` hardcodes the Pending badge as `outline` (line 90), and the screenshots confirm it.
- Copy matches the contract strings: "Choose at least one host.", "No rollouts yet", "No updates yet", the offline-history sentence, "Cancel without waiting for the host that is updating", and "Follow the rollout", which is asserted in the test.

**Every State Is Shown (17).** Screenshots show these states at the cited viewports and themes:
- Hosts page: loading, error and empty.
- Host page: loading, error and not-found.
- Update history: loading, error, empty, populated and offline.
- Rollouts page: loading, error, empty, worst case and failed.
