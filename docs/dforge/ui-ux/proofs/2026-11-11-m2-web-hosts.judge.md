## Changes since round four, checked

- **Cancel rollout keeps its dialogs open after the rollout stops running.** `CancelRollout` hides only the button when the rollout leaves running or draining. Its dialogs stay mounted, and focus goes to the card's `h2` (which has `tabIndex=-1`). The test "UX-10, UX-11: a cancel without force sends force false and keeps its result once the rollout is cancelled" covers this. The stub returns "cancelled" after apply, and the test asserts that:
  - the plan input is `force: false`;
  - the Cancel rollout button disappears;
  - the change dialog still shows "completed";
  - after Escape, focus is on the "1.2.3 (stable)" heading.

  This closes most of last round's UX-10 gap, the cancelled state after a cancel.
- **One Start rollout flow serves both buttons.** `RolloutsPage` owns a single `StartRolloutFlow` above the switch between the empty state and the list. The test "a rollout started from the empty state keeps its result and returns focus to the header" starts a rollout from the empty-state button. After the list refreshes and the empty state unmounts, the dialog still shows "completed", and Escape returns focus to the header's button. The e2e start-rollout steps and the UX-9 started shots (375 light, 1440 dark) show 1.4.0 (stable) listed first, with a focus ring on the header's Start rollout.
- **Start rollout explains a host list it cannot read.** `StartRolloutTrigger` shows "The host list could not be read: <message>" beside the disabled button and links the two with `aria-describedby`. A Vitest test covers it. No screenshot shows it, and the contract does not require one.
- **Focus goes to the revoked host's controls after a revoke.** The new test "UX-3, UX-11: closing the dialog after a revoke focuses the revoked host's controls" passes the revoked host back into the component. After Escape, focus lands on "New enrollment token". The report's UX-3 row does not cite this test, but it exists.
- **Each rollout's host-table scroller has a unique name.** The name is now "Hosts of the <version> rollout created <time>", so two rollouts of the same version no longer share it.
