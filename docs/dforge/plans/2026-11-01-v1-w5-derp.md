# v1 wave 5: DERP server, region and probe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the skill the **Execution:** line names — dforge:subagent-driven-development for `subagent`, dforge:executing-plans for `inline`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build wave 5 of the v1 completion spec: the `derp` module (the agent's `derp.server.install`, `derp.server.uninstall`, `derp.binary.update` with its recovery handler, `derp.cert.renew` and two agent reads; the controller's `derp.server.probe`, two internal reads, the `derp.servers` service and resource, and the composites `derp.server.deploy`, `derp.server.upgrade`, `derp.cert.rotate`, `derp.region.set`, `derp.region.remove` and `derp.server.remove`), the verified derper release artifact (`release/derper.version`, `releasetool derper`, `derper.json`, the agent's fetch), the `/derp` web page, the M5 DERP harness test, and register row 300 (the latency probe URL).

**Architecture:** The `derp` module follows the tailscale module's shape: a `module` value holding an internal struct `dp` whose methods construct one `core.ActionDef` per action, a `deps` struct that tests replace with fakes, a module-private test host, and one registration task that wires every constructor into `Manifest()` and commits the schema snapshots. Pure logic lives in two packages without I/O: `derp/server` (unit file, flags, certificate pin and port rules) and `derp/artifact` (the derper version and manifest, plus the verified fetch over `internal/update`). The agent half's long actions are task actions (`core.DefineTask`, spec 1.3c); the binary update is an agent-local transaction journaled in its own table with a module recovery handler (1.3b). The controller half reads agents through `env.Agents`, the tailnet through new exported reads of the tailnet module, and computes policy edits and fallback checks in leading Internal read steps of its composites, because a composite's `Steps` reads only its input and the controller database.

**Tech Stack:** Go 1.26 (standard library, `internal/platform/tslocal`, `internal/platform/netstat`, the `internal/platform` exec allowlist with `useradd`/`userdel` for `darkpanel-derp`, `internal/update` with minisign), SQLite through `internal/core/store`, React 19 + TypeScript + TanStack Query + darkraise-ui (Vitest), the KVM harness in `test/harness` (GitHub Actions `harness.yml`), the release workflow `release.yml`.

```go
// DerperVersion is the derper release this Darkpanel builds, publishes and installs; release/derper.version holds
// the same value (a test reads that file and compares).
const DerperVersion = "v1.104.1"

// ManifestName is the release asset listing the derper builds.
const ManifestName = "derper.json"

// Arches are the architectures a release builds derper for, in order.
var Arches = []string{"amd64", "arm64"}

// BinaryName is the release asset of derper version for arch: "derper-" + version + "-linux-" + arch
// (BinaryName("v1.104.1", "amd64") == "derper-v1.104.1-linux-amd64").
func BinaryName(version, arch string) string

// PinVersion is the tailscaled version a DERP host is pinned to: DerperVersion without its leading "v" ("1.104.1").
func PinVersion() string

// Manifest is derper.json.
type Manifest struct {
	DarkpanelVersion string            `json:"darkpanelVersion"` // a version update.ParseVersion accepts, without "v"
	DerperVersion    string            `json:"derperVersion"`    // ^v[0-9]+\.[0-9]+\.[0-9]+$
	Artifacts        map[string]string `json:"artifacts"`        // arch → 64 lower-case hex digits; exactly the keys of Arches
}

// ParseManifest decodes b strictly: unknown members, a missing member, a version that does not match its pattern,
// an arch outside Arches, a missing arch or a hash that is not 64 lower-case hex digits is an error naming it.
func ParseManifest(b []byte) (Manifest, error)

// Encode is m as two-space indented JSON with a trailing newline (map keys sorted, as encoding/json sorts them);
// it validates m as ParseManifest does first.
func (m Manifest) Encode() ([]byte, error)
```

Task 9 writes `fetch.go`:

```go
// Source is where Fetch reads a release.
type Source struct {
	Client   *http.Client
	BaseURL  string                                            // trustedkeys.BaseURL() in production
	Keys     []trustedkeys.Key                                 // trustedkeys.Keys() in production
	Releases func(ctx context.Context) ([]update.Release, error) // (*update.IndexSource).Releases in production
}

// Fetch returns derper version want for arch from the release of Darkpanel version dpVersion: it finds dpVersion in
// Releases (absent: update.not_found, "darkpanel <dpVersion> is not a published release; a DERP server needs a
// released darkpanel"), reads ManifestName with update.DownloadAsset (at most 64 KiB), checks the manifest's
// darkpanelVersion equals dpVersion (else update.signature_invalid) and its derperVersion equals want (else
// update.not_found, "release <dpVersion> carries derper <v>, not <want>"), reads BinaryName(want, arch) with
// update.DownloadAsset (at most 128 MiB) and checks its SHA-256 against the manifest's artifacts[arch] (else
// update.signature_invalid). sha is the 64 lower-case hex digits of the binary.
func Fetch(ctx context.Context, src Source, dpVersion, want, arch string) (bin []byte, sha string, err error)
```

### DERP server unit (from Task 7)

Package `internal/modules/derp/server`, pure (no I/O):

```go
const (
	ServiceUser    = "darkpanel-derp"
	BinaryPath     = "/usr/local/lib/darkpanel/derper"
	BinaryNewPath  = BinaryPath + ".new"
	BinaryPrevPath = BinaryPath + ".prev"
	UnitName       = "darkpanel-derper.service"
	UnitPath       = "/etc/systemd/system/" + UnitName
	StateDir       = "/var/lib/darkpanel/derp"
	CertSubdir     = "certs"
	CertDir        = StateDir + "/" + CertSubdir
	KeyPath        = StateDir + "/derper.key"
	HTTPPort       = 80
	HTTPSPort      = 443
	STUNPort       = 3478
	ModeLetsEncrypt = "letsencrypt"
	ModeIP          = "ip"
	RuleLabel       = "derp"
	PinPrefix       = "sha256-raw:"
)

// Config is one server's configuration.
type Config struct {
	Mode          string // ModeLetsEncrypt | ModeIP
	HostName      string // letsencrypt: a DNS name; ip: the public IP literal in canonical form
	VerifyClients bool
}

// CheckConfig refuses, as request.invalid_input with a field error: a Mode other than the two (/mode); for
// letsencrypt, a HostName that is not a lower-case DNS name of at most 253 bytes with at least two labels, or is an
// IP literal (/hostName); for ip, a HostName that is not a canonical IP literal, or is not global unicast, or is
// private, loopback, link-local, unspecified or a Tailscale address (100.64.0.0/10, fd7a:115c:a1e0::/48) (/hostName).
func CheckConfig(c Config) error

// Flags is derper's argument vector after the program path, in this order:
// -c KeyPath -a :443 -http-port 80 -stun -stun-port 3478 -hostname <HostName> -certmode <letsencrypt|manual>
// -certdir CertDir, then -verify-clients when VerifyClients.
func Flags(c Config) []string

// UnitFile is the unit text (Contracts "DERP unit text").
func UnitFile(c Config) []byte

// CertFiles is the ip mode's certificate and key file names inside CertDir: "<ip>.crt", "<ip>.key"; ok is false
// for letsencrypt (derper's own cache, never pinned or renamed).
func CertFiles(c Config) (crt, key string, ok bool)

// Pin is PinPrefix + the lower-case hex SHA-256 of der.
func Pin(der []byte) string

// ParseCert decodes the first CERTIFICATE block of pemBytes: its DER and NotAfter.
func ParseCert(pemBytes []byte) (der []byte, notAfter time.Time, err error)

// RuleID is the firewall rule id of one DERP port of host hostID: "0" + the first 25 characters of the Crockford
// base32 (alphabet 0123456789ABCDEFGHJKMNPQRSTVWXYZ, no padding) of SHA-256("darkpanel/derp/" + hostID + "/" + port),
// port one of "80/tcp", "443/tcp", "3478/udp". It matches the firewall's ULID id pattern.
func RuleID(hostID, port string) string

// PortRules are the three rules derp.server.deploy adds, in port order 80/tcp, 443/tcp, 3478/udp: each
// model.Rule{ID: RuleID(hostID, port), Action: allow, Direction: in, Proto: tcp|udp, From: "any", To: "any",
// ToPort: "80"|"443"|"3478", Family: both}, with no comment (firewall.rules.apply's label adds it).
func PortRules(hostID string) []model.Rule
```

### Derper release build (from Task 8)

`release/releasetool` gains the subcommand `releasetool derper <darkpanel version> <out dir> [-arch amd64|arm64]` in the new file `derper.go` (and the usage text in `main.go`): for each arch (the one given, else every `artifact.Arches` entry) it builds `tailscale.com/cmd/derper@artifact.DerperVersion` in a fresh temporary module (`go mod init derperbuild`, `go get tailscale.com/cmd/derper@<v>`, then `go build -trimpath -ldflags "-s -w" -o <out>/<artifact.BinaryName(v, arch)> tailscale.com/cmd/derper` with `CGO_ENABLED=0 GOOS=linux GOARCH=<arch>` and the caller's `GOTOOLCHAIN`), writes `<out>/derper.json` (`artifact.Manifest{<darkpanel version>, v, {arch: sha}}.Encode()`) only when every arch of `artifact.Arches` was built, and, when `<out>/checksums.txt` exists, rewrites it as `release/package.sh` writes it: one `<sha256>  <name>` line per regular file of `<out>` other than `checksums.txt` and `*.minisig`, sorted by name in byte order. The build step is a function value (`type derperBuilder func(ctx context.Context, version, arch, dst string) error`) so tests replace it; the darkpanel version is checked with `parseVersion`. `.github/workflows/release.yml` runs `go run ./release/releasetool derper "$VERSION" <the release directory make release wrote>` right after `make release`, and `release/README.md` documents the step and that bumping `release/derper.version` promptly after a Tailscale security release is part of the release routine (spec 4.3).

### DERP install, update and renewal effects (Tasks 15, 16, 19, 20, 24)

`derp.server.install` plans: `CheckConfig`; refuses an existing `derp_server` row (`request.invalid_input`, "a DERP server is already installed on this host"), a listening socket on 80/tcp, 443/tcp or 3478/udp (`derp.port_in_use`, naming each port and its process), and an existing user, binary, unit file or service directory that `env.Files.Owns` does not record as the module's (`request.invalid_input`, naming it); `VerifyClients` false adds the diff line `! client verification is off: any node that knows the region can relay through it`.
