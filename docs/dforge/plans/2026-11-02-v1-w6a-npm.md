# v1 wave 6a: Nginx Proxy Manager Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the skill the **Execution:** line names — dforge:subagent-driven-development for `subagent`, dforge:executing-plans for `inline`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build wave 6a of the v1 completion spec: the `npm` module (the agent's instance deploy with its bootstrap, confirm-public, remove, status, upgrade transaction with its recovery handler, network attachment claims, proxy hosts, access lists, certificates, list reads and the audited password reveal; the controller's check reads, the fleet instance read and the composites `npm.instance.deploy-public`, `npm.expose.container`, `npm.expose.remove`, `npm.admin.expose`, `npm.admin.unexpose`), the docker module's log-secret registration (register row 294, NPM half), the `/hosts/:id/npm` web page, the container Expose action and the every-page admin-exposure banner, the M6 NPM harness test against Pebble with its workflow job, and two fixes that keep `main` green (register rows 302 and 7–10, 13).

**Architecture:** The `npm` module follows the derp and docker modules' shape: a `module` value holding an internal struct `nm` whose methods construct one `core.ActionDef` per action, a `deps` struct that tests replace with fakes (a fake Docker Engine and the fake NPM server of `internal/modules/npm/fake`), a module-private test host, and one registration task that wires every constructor into `Manifest()` and commits the schema snapshots. Pure logic lives in packages without I/O: `npm/npmapi` (the typed client of NPM's REST API) and `npm/proxy` (the custom-location configuration, the upstream reservation rules and the supported-target rule). Agent actions drive Docker through `internal/platform/dockerapi` and NPM through `npmapi` on `127.0.0.1:81`, journal every Engine and NPM object as a non-local effect with the identities of spec 6, and keep their bookkeeping (instance, reservations, attachment claims, upgrade transactions, watched identities) in agent tables. Controller composites decide their steps from their input alone; host facts they depend on are checked by leading controller-side internal read steps.

**Tech Stack:** Go 1.27 (`go.mod`: `go 1.27`, toolchain `go1.27.3`) (standard library, `internal/platform/dockerapi`, `internal/platform/netfilter`, `internal/modules/firewall/loaded` and `dockerfw` for the raw-table check), SQLite through `internal/core/store`, React 19 + TypeScript + TanStack Query + darkraise-ui (Vitest), the KVM harness in `test/harness` with Pebble and `pebble-challtestsrv` (GitHub Actions `harness.yml`).

### NPM API client (from Task 6)

### Proxy rules (from Task 7)

Package `internal/modules/npm/proxy`, pure:
- `func Location(forwardScheme, forwardHost string, forwardPort int, panel bool) npmapi.Location` — path `/`, the forward target, and `AdvancedConfig` exactly `proxy_set_header X-Darkpanel-Client $realip_remote_addr;` plus, when `panel`, a second line `proxy_read_timeout 3600s;` (lines joined by `\n`, no trailing newline). It never emits a header the NPM template sets (spec 6 list, as Task 1 confirms).
- `type Reserved struct{ NPMAddrs []netip.Addr; PanelNetwork netip.Prefix; PanelGateway netip.Addr }` and `func CheckUpstream(r Reserved, host string, port int, parent string) error` — refuses with `npm.reserved` an upstream of `127.0.0.1`, `localhost` or an NPM address on port 81 unless `parent == "npm.admin.expose"`, and an upstream inside the panel network or equal to the panel gateway unless `parent == "panel.exposure.add"`.
- `func Target(endpoints map[string]Endpoint, network string) error` with `type Endpoint struct{ Driver string; UserDefined bool }` — `npm.unsupported_target` with the reason `connect the container to a user-defined network` unless the container is on `network` and `network` is a user-defined `bridge`; `func FirstTargetNetwork(endpoints map[string]Endpoint) (string, bool)` — the first supported network in name order (used by the web's default and by the harness).

## Assumptions (evidence)

- The `npm` module is a registered skeleton: `internal/modules/npm/npm.go` declares only `ID`, `module`, `Module()` and an empty `Manifest()`, with `TestManifestIsASkeleton` (read 2026-11-02); `internal/cli/npm.go` returns no command, and every action gets a generated CLI command, so no CLI file changes; `web/src/modules/registry.ts:30-38` already registers `npm` with `routes` and the container action `{id: "npm.expose", label: "Expose"}`, and `registry.test.tsx:42-48` pins those ids (unchanged by this plan).
- The error codes `npm.unhealthy`, `npm.not_public`, `npm.reserved`, `npm.unsupported_target`, `npm.setup_failed` exist (`internal/core/errcode/errcode.go:107-110,131`), as do `docker.owned`, `docker.in_use`, `docker.engine_unavailable`, `plan.state_changed`, `request.invalid_input`, `not_found` and `lock.held` (`errcode.go:17-37,90-92`).
- `dockerapi` offers every Engine call the module needs: containers (`CreateContainer`, `StartContainer`, `StopContainer`, `RemoveContainer`, `InspectContainer`, `ListContainers`), networks (`CreateNetwork`, `ConnectNetwork` with `EndpointSettings`, `DisconnectNetwork`, `InspectNetwork`, `RemoveNetwork`), volumes (`CreateVolume`, `InspectVolume`, `RemoveVolume`), images (`PullImage`, `InspectImage` by digest reference) and the only archive API, `CopyFromContainer` and `CopyToContainer`, which work on a stopped container (`internal/platform/dockerapi/containers.go:182-257`, `networks.go:66-122`, `volumes.go:30-62`, `images.go:106-139`, `streams.go:225-239`). No exec, no `tar` in the exec allowlist (`internal/platform/exec_rules.go`).
- Ruling: the upgrade archives each volume by `CopyFromContainer` of `/data` and `/etc/letsencrypt` from the stopped original container into one managed file per volume (`<lowercased change id>-data.tar`, `-letsencrypt.tar`, matching the default managed-dir pattern `^[a-z0-9][a-z0-9._-]{0,63}$`), written whole with `WriteManaged` and verified by SHA-256 read back through the `readFile` dep; restore removes the new container and both volumes, recreates the volumes and the original container (not started) from the journaled configuration, `CopyToContainer`s each archive to the mount's parent directory, and starts it.
- Ruling: Docker 28.0+ with raw protection is the `Available` check of `npm.instance.deploy`: `dockerapi.Info().ServerVersion` at least 28.0, and Docker's variant of the `raw` table read through `loaded.Reader{}.ReadVariant` (`internal/modules/firewall/wire.go:45`, `docker_state.go:220`) and decided by `dockerfw.RawProtected` (`internal/modules/firewall/dockerfw/detect.go:88`); the exec rule for `-t raw` is not bound to a module (`internal/platform/exec_rules.go:35,146`). Task 11 builds it as Contracts "NPM shared internals" `rawVia` states; whether every helper it names is exported: unverified — Task 11 reads `docker_state.go:195-232` and stops and reports if one is not.
- Ruling: a composite's `Steps` reads only its input and the controller database (`internal/core/contract.go:303-311`), so `npm.instance.deploy-public` takes `Integration` in its input (the web fills it from `firewall.docker`'s `enabled && supported`) and its leading `check` read step refuses at apply when the host disagrees; `npm.expose.container` takes `Network` in its input (the web fills it with the first supported network in name order) so the `network` step's dry run refuses an unsupported target in the preview (`npm.network.attach` with `Target` checks it at plan); the public-instance check runs at apply in the leading `public` read step.
- Ruling: a "confirmed `ports` step" is read from the firewall's stored container policy (`firewall.docker` `bindings`), because a firewall change that is not confirmed reverts and leaves no allow binding; the agent's npm module cannot see the firewall's state, so the check is controller-side (`npm.public.check`).
- Ruling: reservations are recorded and released by the child actions themselves from `Env.Call.ParentAction` (spec 1.5: set only by the controller), keyed by the exposure's hostname: a child of `npm.admin.expose` or `panel.exposure.add` records what it creates; a child of `npm.admin.unexpose` or `panel.exposure.remove` may remove a reserved object of its own owner and drops that exposure's rows, so the certificate an admin exposure leaves can then be deleted with `npm.certificate.remove` (spec 6: "the certificate stays, and deleting it is the separate, explicitly confirmed `npm.certificate.remove`").
- Ruling: the docker module's log-secret seam becomes a registration table in package docker (Contracts "Docker log secrets"), because no core API exists for it (register row 294) and the core is frozen; registration happens only in `init`, so the table is constant at run time.
- Ruling: there is no app-wide banner extension point (`web/src/modules/types.ts`, spec 1.12); `web/src/shell.tsx` is not frozen (spec 1.12 "Not frozen"), so Task 10 adds the npm banner to it directly, fed by the controller read `npm.instances`; wave 8 adds its panel banner beside it.
