# M2 Web Hosts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the skill the **Execution:** line names — dforge:subagent-driven-development for `subagent`, dforge:executing-plans for `inline`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the M2 spec's web host management (section 10, work package P7): the R27 host-list columns, a host Overview tab with revoke, delete, enrollment token, update policy, update now and update history, and a Rollouts page.

**Architecture:** Pure web work in `web/src` over actions that already exist and are pinned by `schemas/` snapshots; every change runs through the existing `ChangeDialog` (plan, typed confirmation, apply). State boards come first as a development-only Vite page rendered to PNG by Playwright, and the proof is the ui-ux walkthrough against the `web/e2e` mock API.

**Tech Stack:** React 19, darkraise-ui 6.9.6, TanStack Query, react-router, Vitest with Testing Library and vitest-axe, Playwright 1.64.

**Spec:** docs/dforge/specs/2026-10-19-m2-fleet-lifecycle-design.md

## Global Constraints

- Copy is plain, sentence case, verbs on buttons (`docs/dforge/ui-ux/profile.md`); the exact strings are the ones the spec's `## UI/UX contract` and this plan quote.
- Components and tokens come from darkraise-ui 6.9.6; no raw colours or sizes outside its tokens.
- Every change goes through `ChangeDialog` (`web/src/components/change-dialog.tsx`); no page calls `applyPlan` itself.
- Every Vitest test that proves a contract item has a name starting with that item's ID and a colon, for example `test("UX-3: revoking a host ...")`.
- Each new or changed page has a vitest-axe test (`expectNoAxeViolations` from `@/test/a11y`) with no violations.
- Times render with `formatTime` from `@/lib/format`; a null time renders as the string that function returns for null (`—`).
- `web/src/boards/` and `web/boards.html` are development-only: `vite build` keeps `index.html` as its only entry, so nothing under `web/src/boards/` is imported by `web/src/main.tsx` or any page.
- Tests use `stubFetch` and `renderWithProviders` from `@/test/utils`; no test talks to a network.
- File order: Task 5 creates `web/src/pages/host-overview.tsx` with an empty `<div className="flex flex-wrap gap-2">` under the "Updates" card title and another under the "Enrollment and removal" card title; Tasks 6, 7 and 8 each render their component in one of them. Task 9 creates `web/src/pages/rollouts.tsx` with an empty `PageHeader` actions element that Task 10 fills.

## Assumptions (evidence)

- Every action the pages call exists with the shapes above: `schemas/core.host.*` and `schemas/core.update.*` snapshots and `internal/core/fleet.go:79-257` (read 2026-11-11).
- `core.host.token` and `core.host.delete` refuse the local host and accept only pending or revoked hosts: `docs/user/administration.md` Hosts section and `internal/controller/coreactions/hostenroll.go` (`tokenGuards`), read 2026-11-11.
- No action reads a host's stored update policy; the `core.host.update-policy` plan diff shows the stored policy (`-`) beside the new one (`+`): `internal/controller/coreactions/hostpolicy.go` Plan, read 2026-11-11. This is the contract's OP-4 deviation.
- No action lists published releases (no such schema under `schemas/`, 2026-11-11), so versions are typed: OP-5.
- `core.update.status/v1` runs on the agent of the host named in the path (`/api/v1/hosts/<id>/actions/...`), so it is not sent for an offline host: `readAction`'s `hostId` argument in `web/src/api/client.ts`.
- `vite build` builds only `index.html` (default `rollupOptions.input`), so `web/boards.html` is served by the dev server and never shipped: unverified — Task 1 verifies it with `make build` and a check that `web/dist/boards.html` does not exist.
- Playwright's `webServer` already serves the app for `web/e2e/*.pw.ts` (`web/playwright.config.ts`); `E2E_CHROMIUM` names a local Chromium when the pinned build is absent (`docs/accessibility.md` line 10).
