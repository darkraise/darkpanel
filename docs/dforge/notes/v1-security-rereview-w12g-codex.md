## Row 191: Starts Darkpanel does not make are not verified

- Verdict: **PARTIAL**
- Attack path: An operator prepares a forward to address A; an Engine, host, or restart-policy start subsequently gives NPM A. Without a successful background repair, the forward can reach NPM’s administrative services.
- Fix: [reconcile.go:261](/root/repositories/darkpanel/internal/modules/npm/reconcile.go:261) registers the five-minute task and Docker watch. [background.go:159](/root/repositories/darkpanel/internal/agent/runtime/background.go:159) runs an initial pass and subsequent timed/event-driven passes. Reconcile rechecks under the npm lock, disconnects offending external networks, retains claims, reloads, and stops NPM when a disconnect fails. The action itself requires admin; the background principal supplies that scope.
- Regression tests: `TestW12gReconcileDisconnectsNPMFromAForwardedAddress`, `internal/modules/npm/reconcile_action_test.go:44` — reproduces: yes for the resulting unsafe state; fails on revert: yes. `TestW12gReconcilePassAppliesOnAHit`, `internal/modules/npm/reconcile_task_test.go:49` — reproduces: yes; fails on revert: yes. `TestW12gReconcileWatchWakesOnStartAndConnect`, same file:205 — reproduces: yes with simulated events; fails on revert: yes. `TestBackgroundStartsEnabledTasks`, `internal/agent/runtime/background_test.go:285`, and `TestBackgroundEvery`, same file:302 — reproduce: yes for scheduling; fail on revert: yes. Harness `reconcileUndoesAStartDarkpanelDidNotMake`, `test/harness/m6_npm_test.go:1252` — reproduces: partly; it deliberately reconnects NPM at the target address, rather than proving restart-policy allocator behavior; fails on revert: yes.
- Residual: **Repairable hits can be permanently mistaken for the accepted own-network exception.** Steps:
  1. A pass and its plans see a named forward resolving to an address NPM holds on an external network.
  2. During the action’s Apply scan, a transient failure of any forwarded name makes `forwardAnswers` return no answers. `reconcileScan` consequently discards all named targets, finds no hit, and Apply changes nothing.
  3. Resolution recovers before Verify. Verify finds the original hit and returns `npm.reserved`.
  4. The lifecycle records a failed change and releases the lock. The task nevertheless stores its original hit key for **every** `npm.reserved` error.
  5. Later healthy passes find that identical external-network hit and return without applying. Suppression lasts until the key changes, a no-hit pass occurs, or the task restarts.

  The traced chain is [network_claims.go:1275](/root/repositories/darkpanel/internal/modules/npm/network_claims.go:1275), [reconcile.go:94](/root/repositories/darkpanel/internal/modules/npm/reconcile.go:94), Apply at line 163, Verify at line 233, and suppression at lines 280 and 289; lifecycle execution and failure settlement are `internal/core/lifecycle/apply.go:395` and `settle.go:103`.

  **Confirmed control-flow defect; end-to-end exploitation plausible; medium**, because it requires a particular lookup interleaving and an unsafe address state. An operator can supply forward names and change the availability of ordinary Docker alias holders without acquiring the npm lock. Docker allocation and nginx behavior remain inference. **Owner-accepted: no.** D3 limits remembered failures to hits on `darkpanel-npm`; U3 does not authorize suppressing an external-network repair. Row 217’s claim that the next pass necessarily has a different key is not generally true.
- Residual: Held-lock skips, indefinite `needs_repair` lock retention, startup/API delay, own-network hits left running, and DNS-driven unattended disconnects remain. **Confirmed; medium, with the underlying forwarding consequence conditional; owner-accepted: yes**, U3 and threat-model line 297. An operator can indirectly trigger the accepted disconnect through a changed forward answer, although they cannot directly invoke the admin-only action.

## Other observations

- **The ten-second attach exposure claim is not enforced as a total deadline; confirmed; low.** `afterJoin` inspects using the caller’s context at `network_claims.go:909`; only `leave` starts the ten-second timeout at `:1002`. A delayed connect response or inspection precedes that timeout. Lost-connect recovery also has its separate, longer deadline at `:945`. `docs/security/threat-model.md:298` and D1 therefore overstate the bound. This does not negate the verified removal of listings/lookups before comparison of recorded targets.

- **Pending execs can be forgotten after uncertain transport errors; confirmed; low.** At `nginx_exec.go:163`, a failed `ExecStart` records `pending` only when the context has ended. At `:174`, a failed `ExecInspect` before the deadline returns without recording it. If the Engine started the command but its answer was lost, another reload can start while the earlier command remains active. Actual concurrent command execution is inference. The existing timeout and 404 tests do not cover these branches.

- **The new-worker witness is weaker than D2’s description; confirmed; low.** `nginx_exec.go:77` takes the baseline before `nginx -t`, rather than immediately before the signal. `workers` at `:132` ignores PPID and accepts command-prefix matches; `newWorker` accepts any newly appearing matching PID. An unrelated worker replacement during the test can therefore satisfy the witness. Threat-model line 299 acknowledges unrelated respawns, but no explicit owner acceptance of this precise witness weakness was found. No `operate`-only method of forcing a false witness was established.

- **One failed lookup discards successful answers for every other name; confirmed; medium limitation, accepted by D3/U3’s literal-only fallback.** `forwardAnswers` returns `nil` on one uncertain name at `network_claims.go:1275`, and `reconcileScan` explicitly discards answers at `reconcile.go:96`. Consequently, an unrelated unresolved name can hide an otherwise resolvable named hit. This also enables the additional, unaccepted permanent-suppression sequence under row 191.

- **Reconcile compares literals after waiting for name resolution; confirmed; low.** `reconcile.go:94` performs lookups before building and comparing the literal-first target list at `:101`. D3’s statement that the literal comparison “has been made” when lookups fail is inaccurate as an ordering claim. A failed lookup does not discard literal targets, but it delays their comparison.

- **Some threat-model timing and DNS statements are too absolute; confirmed; low.** `docs/security/threat-model.md:295` and `:347` say re-pointed names are not checked again, although reconcile resolves them periodically. Line 298’s “at most 5 minutes” ignores held locks, failure backoff, and pass duration. `background.go:172` schedules the interval after a pass ends; initial reconcile Docker reads have no dedicated pass deadline, and the shared NPM HTTP client has a fifteen-minute timeout (`deps.go:182`).

- **Row 204’s regression test does not pin error classification; confirmed; low.** `TestW12gAttachWhoseConnectAnswerIsLostChecksTheAddress`, `w12g_attach_test.go:320`, checks text and disconnection but not `core.IsDefinite`, the retained engine code, or the detach-inverse caller. The implementation preserves them by reading; this test would not detect every regression in that contract.

- **The A6 output-leak assertion has no sensitive-output stimulus; confirmed; low.** `w12g_security_followup_acceptance_test.go:651` searches for nginx output, but its exec fake at `:434` supplies no output-bearing response. That assertion alone cannot demonstrate redaction. The stronger evidence is structural: the production exec adapter attaches no stdout/stderr and never reads a command stream.

- **A20 does not exercise lifecycle epoch invalidation; confirmed; low.** `w12g_security_followup_acceptance_test.go:1393` inserts a fake container and calls inverses directly. It does not execute an intervening Docker lifecycle change or a composite unwind. It demonstrates endpoint/claim reversal, but cannot establish the full composite-and-lock-epoch acceptance by itself.

- **The reported live harness result remains external evidence.** Source inspection confirms that the current steps exercise the real attach, upgrade refusal, and reconcile behavior. This review did not execute or retrieve run `43711297246`.
