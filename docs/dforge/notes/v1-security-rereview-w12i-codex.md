## New findings in the w12i changes

- **A refused connect can claim ownership of somebody else’s attachment. Confirmed bookkeeping defect; triggering concurrency plausible; low.** If NPM is absent at the initial check, then another actor joins it before Darkpanel’s connect is refused, successful `afterJoin` falls through to success with the original `ck.preexisting == false`. The endpoint is recorded as made and the new claim as non-preexisting. An `operate` caller can subsequently detach that claim, or undo the attach, disconnecting the concurrent attachment. A requested static address is also not rechecked against that endpoint. This needs a concurrent external join; ordinary Docker actions refuse the module-owned NPM container. The new test covers only the unsafe-address refusal, not this success path. See [network_claims.go:400](/root/repositories/darkpanel/internal/modules/npm/network_claims.go:400), `:423`, `:554`, and `:785`. The precise bookkeeping case is not explicitly owner-accepted.

- **Detach undo does not bind its driver check to the network it connects. Confirmed identity gap; exploitation plausible; low.** `joinGuard` checks the inspected network but returns only targets. Undo then connects by name. If an empty external bridge is removed and recreated under the same name after inspection, undo can connect to the replacement without checking its driver. Docker management actions use the separate `docker` lock; `afterJoin` checks addresses, not driver or network ID. Actual replacement/connect timing is **Engine-behavior inference**. Attach uses the inspected ID and avoids this particular substitution. See [network_claims.go:831](/root/repositories/darkpanel/internal/modules/npm/network_claims.go:831) and `:894–909`. No explicit acceptance found for this narrower race.

- **New residual wording conflates an unanswered name with a failed lookup. Confirmed; low.** Threat-model line 297 says that while *any* forwarded name gets no answer, reconciliation compares only literals. A definite DNS not-found does not fail `forwardAnswers`; other names’ answers remain available and are compared. The literal-only fallback occurs on a returned lookup error. See [threat-model.md:297](/root/repositories/darkpanel/docs/security/threat-model.md:297), `network_claims.go:1280–1284`, and `reconcile.go:94–101`.
