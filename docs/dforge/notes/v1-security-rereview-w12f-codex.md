- Verdict: **PARTIAL**

[proxy/upstream.go:38](/root/repositories/darkpanel/internal/modules/npm/proxy/upstream.go:38) reserves every port of NPM’s names and addresses; [proxyhost_add.go:398](/root/repositories/darkpanel/internal/modules/npm/proxyhost_add.go:398) also checks resolved addresses. - Regression tests: `TestV1r08ReservesEveryPortOfNPMsNamesAndAddresses`, [proxy/upstream_test.go:120](/root/repositories/darkpanel/internal/modules/npm/proxy/upstream_test.go:120) — reproduces: **yes**, including port 3000, IPv4, IPv6, aliases and network-qualified names; fails on revert: **yes**. `TestPaReservedUpstreams`, [proxyhost_add_test.go:315](/root/repositories/darkpanel/internal/modules/npm/proxyhost_add_test.go:315) — reproduces: **yes** at the action boundary; fails on revert: **yes**. The named regressions for the November 14 residuals are assessed under rows 142, 176 and 177.
- Residual: **A literal-address conflict after attach can remain exposed while unrelated names are resolved.** An `operate` caller can arrange an ordinary container holding address A, create a proxy host forwarding to literal `A:3000`, and start an Engine-assigned NPM attach to that network. After the forward check, disconnect the holder so the Engine can assign A to NPM. Separately, after the first nginx reload, disconnect a container whose name another proxy host forwards to. If that name’s fallback lookup stalls, NPM remains connected at A throughout that lookup. [network_claims.go:882](/root/repositories/darkpanel/internal/modules/npm/network_claims.go:882) calls `forwardTargets` **before** comparing even literal targets; [network_claims.go:971](/root/repositories/darkpanel/internal/modules/npm/network_claims.go:971) resolves all names before returning any targets, under the six-second lookup deadline at line 999. Disconnection happens only after this returns. The npm and Docker actions have different locks, so those Docker operations are not excluded. **Plausible; high; owner-accepted: no.** The ordering and available actions are confirmed; successful timing, Docker’s allocation of A and requests reaching NPM during the interval are inference, not a live demonstration. D3’s accepted start-to-inspection design does not describe this caller-extended interval on an already-running NPM. Existing tests assert eventual disconnection, not absence of exposure during lookup.
- Residual: Repointing a caller-controlled DNS name after application, or obtaining different answers inside nginx and on the agent, still reaches reserved addresses. **Confirmed absence of continuous checking; high impact if exercised; owner-accepted: yes**, spec D7 and [threat-model.md:349](/root/repositories/darkpanel/docs/security/threat-model.md:349). The nginx forwarding consequence is inference.

- **A reload used as a join precondition can remove the selected proxy host’s active configuration. Plausible; medium availability.** An operate caller can initiate a join and concurrently disconnect an ordinary container whose name the selected host uses, timing the loss between NPM’s first and second configuration tests. According to the pinned-image reading at [w12e-evidence.md:234](/root/repositories/darkpanel/docs/dforge/notes/w12e-evidence.md:234), the failed second test renames the selected host’s file to `.err`; if the remaining configuration passes, NPM reloads without that host. Reconnecting the upstream alone does not regenerate the removed file. Darkpanel returns a definite join refusal from [network_claims.go:838](/root/repositories/darkpanel/internal/modules/npm/network_claims.go:838), without journaling or compensating this proxy-host change. The selected host can be unrelated to the requested network. The Darkpanel call path is confirmed; the timed nginx outcome is inference from the recorded image reading. **Not explicitly owner-accepted**; merely recorded at threat-model line 301 and row 188. A name already missing before the first test does **not** establish this `.err` scenario: that first test rejects the update earlier.

- **One disconnected container name can block every new NPM network join. Confirmed; medium availability.** [network_claims.go:949](/root/repositories/darkpanel/internal/modules/npm/network_claims.go:949) collects forwards from every proxy host and location, without filtering by the requested network or by `Enabled`. Thus, under the resolver behavior recorded by the live harness, one broken name prevents joins even to unrelated networks. Already-attached claim-only operations skip this join check. A definite not-found avoids that particular 503, but an enabled static location can still make the pre-join nginx reload fail. The enabled-static-name availability cost is acknowledged in D1; the disabled-host overreach is not separately accepted.
